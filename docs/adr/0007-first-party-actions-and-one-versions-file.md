# CI uses only first-party actions, and tools come from one versions file

GitHub Actions workflows use only actions published by the vendor of the thing they drive (`actions/*` and `github/*` for GitHub, `devcontainers/*` for dev containers), each pinned to a full commit SHA; anything else is a `run:` step or a local composite action. That rules out the usual Rust community actions (`dtolnay/rust-toolchain`, `Swatinem/rust-cache`, `taiki-e/install-action`), so Rust comes from the runner's own rustup, caching uses `actions/cache`, and dev tools (`just`, `cargo-nextest`, `cargo-deny`) are installed by `scripts/install-tools.sh` from upstream release binaries checked against SHA-256s in `.config/tool-versions.toml`. That file is the only place tool versions are written: the dev container and every CI job run the same script. Dependabot updates what it understands (`cargo`, `github-actions`, `devcontainers`, `docker`); the versions file is bumped by hand.
